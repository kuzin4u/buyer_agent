# Пакет для Claude Code: персональный AI-агент-закупщик

Всё, что нужно, чтобы начать писать код: спецификация с закрытыми развилками,
реальный датасет и конфиги, проверенные на нём.

## С чего начать

```bash
python3 validate.py                        # покрытие по датасету
python3 -m unittest discover -s tests      # эталонный тест и слой ввода
```

Прогон применяет конфиги к датасету и печатает покрытие. Занимает секунды, ничего
не пишет. Если цифры совпали с `docs/DATASET.md` — пакет цел, можно читать
`SPEC.md`. Тесты сверяют вывод с `docs/BASELINE.txt` построчно, так что регресс
виден сразу. Внешних зависимостей нет, только стандартная библиотека.

## Что изменилось против исходного ТЗ

Четыре решения, принятые после сверки ТЗ с реальными данными. Подробно — в `SPEC.md`,
разделы 4–7.

1. **Два уровня атома, а не один.** Группа («сметана») — для состава корзины,
   бюджета и напоминаний. SKU (бренд·жирность·фасовка) — для цены, динамики и
   сравнения магазинов. Любое сравнение цен только внутри SKU.
2. **Единица цены зависит от уровня.** На SKU — обе меры: ₽/упаковку показывать
   пользователю, ₽/кг считать. На группе — только ₽/кг.
3. **Словарь брендов — конфиг, а не код.** Пополняется пользователем; правила с
   `confidence: probable` требуют подтверждения.
4. **Чеки без продавца классифицируются по составу позиций.** Их 196 на 336 тыс ₽ —
   четвёртое место по деньгам, и фильтр по имени магазина терял их целиком.
5. **Одна модель на четыре агента, горизонт параметром.** Закупщик — частный случай
   общей операции «профиль × каталог». Слои `core` / `profile` / `matching` / `adapters`
   разводятся сразу, но три адаптера сейчас НЕ пишутся — см. SPEC §8.10 и §9.
6. **Три правила фасовки выведены из самих чеков** — дробное количество, число перед
   «ШТ», голое число в конце. Подняли покрытие с 40,9% до 58,6% без внешних источников.

## Конфиги — рабочий материал, а не фон

Они не финальные и не должны быть. `validate.py` печатает две очереди на
пополнение: топ нераспознанных названий (→ `categories.json`) и топ префиксов без
бренда (→ `brands.json`). Покрытие 75,6% по группам и 58,6% по фасовке — это
рабочая база, а не потолок; каждое добавленное правило проверяется тем же прогоном.

Эти же две очереди должны быть видны пользователю в интерфейсе агента — с
возможностью пополнить словарь одним кликом. Это не диагностика для разработчика,
а часть продукта: словарь брендов будет пополняться всё время жизни агента.

## Чего в пакете нет

- Свежих чеков — выгружает пользователь из «Проверка чеков» (ФНС).
- Ключа ЛЛМ — вставляется пользователем в серверный прокси. Без него работает
  базовый слой.
- Решения по платформе — выбираешь ты, с обоснованием (`SPEC.md` §8.11).

## Статус данных

`data/receipts.json` — реальная история покупок за девять лет, владелец решил
публиковать её вместе с кодом. Ограничений на размещение в публичном репозитории
нет: датасет можно коммитить, разворачивать на публичном хостинге и показывать
в демо.

Что практически из этого следует для кода: не нужен слой обезличивания, не нужны
`.gitignore`-исключения под `data/`, демо-режим может работать прямо на боевом
датасете — отдельный синтетический набор для показа не требуется.

Настройки пользователя (§3.3 SPEC) — другое дело: оценки магазинов, обязательные
продукты и бюджет живут локально у каждого пользователя и в репозиторий не
попадают.
