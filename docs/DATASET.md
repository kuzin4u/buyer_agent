# Датасет `data/receipts.json`

Извлечён из «Реестр_чеков.html» — интерактивного реестра, собранного из выгрузки
приложения «Проверка чеков» (ФНС). Копейки уже переведены в рубли, названия
продавцов частично сведены к читаемым. Отсортирован по дате.

## Схема

Массив объектов. Все поля присутствуют во всех 1744 записях, пропусков нет.

```json
{
  "dt":    "2026-09-05T12:44:00",     // дата и время чека, ISO, без таймзоны
  "shop":  "Глобус",                  // продавец; "не указан" у 196 чеков
  "total": 8806.06,                   // сумма чека, РУБЛИ
  "addr":  "143081, Московская обл...", // адрес; пустая строка у 470 чеков
  "items": [
    { "n": "АРБУЗЫ", "p": 35.4, "q": 6.665, "s": 235.94 }
  ]
}
```

| Поле | Смысл |
|---|---|
| `n` | название позиции, «грязное»: сокращения, артикулы, вес в тексте, латинские гомоглифы |
| `p` | цена за единицу, рубли. У весовых товаров это уже ₽/кг |
| `q` | количество; дробное у весовых (`6.665` = 6,665 кг) |
| `s` | сумма позиции, рубли |

Соответствие боевому ФНС-JSON: `dt` ← `dateTime`, `shop` ← `user`,
`total` ← `totalSum`/100, `addr` ← `retailPlaceAddress`, `n` ← `items[].name`,
`p` ← `items[].price`/100, `q` ← `items[].quantity`, `s` ← `items[].sum`/100.

## Контрольные цифры

Прогон `validate.py` на конфигах версии **1.2**. Полный вывод — `BASELINE.txt`,
он же эталон теста `tests/test_baseline.py`. Если после правки конфигов цифры
изменились, это либо улучшение, которое надо объяснить, либо регресс.

Версия — свойство НАБОРА конфигов, а не отдельного файла: доли считаются по
всем четырём сразу, поэтому сравнивать цифры между версиями можно только
целиком. Все четыре файла помечены 1.2.

Решения, влияющие на эти цифры, — в `DECISIONS.md`. Отдельно стоит знать про
Р-3 (как считается SKU весового товара), Р-15 (хвост единицы измерения снимается
с ключа весового товара — это закрыло П-1 и подняло сравнимые весовые с 8 до 18)
и Р-19 (салфетки и тряпки признаны товаром — это сдвинуло ЗНАМЕНАТЕЛЬ, то есть
все доли сразу).

### Сдвиг версии 1.1 → 1.2

Версия 1.2 приняла критерий исключения из Р-19: из анализа выходит только то,
что не является покупаемым благом. Салфетки и тряпки вернулись в анализ как
бытовые товары, «МАЙКА» отдельным словом больше не считается тарой. Знаменатель
вырос, поэтому сдвинулись ВСЕ доли — ниже обе цифры для каждой:

## Расхождение с демо по сметане — ожидаемое

`reference/sku-demo-smetana.html` показывает 25 SKU и 199 покупок, валидатор на
тех же данных даёт 44 SKU и 320 покупок. Причины: демо считало по одному магазину
(Глобус), а валидатор по всем десяти; демо не ловило написание `СМЕТ.` без
окончания (36 + 32 покупки President 30% в двух фасовках). Это не ошибка ни там,
ни там — разный охват. Ориентироваться на валидатор.

## Оговорки

- Данные уже прошли одну обработку (копейки→рубли, имена магазинов). Боевой
  ФНС-JSON придёт сырым — слой ввода умеет оба формата и определяет его по
  содержимому (`agent/adapters/receipts_fns/loader.py`, тест `tests/test_loader.py`).
- В 254 позициях (221 название) к названию приклеены номер строки в чеке и
  артикул: `10: 4205427 АЛД.ВОДА ЕСС.ЦЕЛ.МИН.ГАЗ.0.5`. Это формат выгрузок
  Продторга (203 позиции, 2023) и SPAR / «Сладкая Жизнь» (51, 2022). Ещё 568
  позиций несут слипшиеся пробелы. И то и другое снимается в слое ввода
  правилом `input_cleanup` (DECISIONS.md Р-7).
- Адрес пуст у 470 чеков, поэтому привязка к конкретной точке сети ненадёжна.
  Сравнение магазинов вести на уровне сети, не точки.
- Датасет открыт по решению владельца: коммитить в репозиторий и разворачивать
  на публичном хостинге можно. Внутри — даты и время покупок, адреса точек,
  полный состав чеков включая аптеки, алкоголь и АЗС; отдельного обезличенного
  варианта не делаем.
