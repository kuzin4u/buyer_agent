# buyer_agent — данные

> Репозиторий: `buyer_agent` · Версия: 0.2 · Дата: 2026-09-23
> Статус: сверено с кодом 2026-09-23 (`/verify`).
> 


## Источник
Собственные чеки ФНС, JSON из приложения «Проверка чеков». Датасет открыт — его можно
держать в публичном репозитории и на публичном хостинге (решение владельца, README «Статус данных»).

- Эталон: `data/receipts.json` (развёрнутый вид, рубли) — `loader.parse_dataset`.
- Боевые выгрузки: `loader.parse_fns_export` (копейки), приём — `agent/intake.py`:
  сырьё как пришло в `data/inbox/`, корпус собирается из эталона и выгрузок с отсевом дублей.
  Оба пути сходятся в одну модель `Receipt`/`Item` (SPEC §3.2).
- Чеки в SQLite не кладутся и в таблицу не материализуются (Р-4).

## Состояние
SQLite `state.db` (`agent/store.py`, путь переопределяется `BUYER_AGENT_DB`) — только изменяемое состояние:

| Таблица | Что хранит |
|---|---|
| `settings` | Настройки §3.3 ключ-значение, значение — JSON (обязательные/исключённые, оценки магазинов, бюджет, флаг кандидатов) |
| `meta` | Служебные отметки: `json_import` — разовый перенос `settings.local.json` в базу выполнен |
| `rules` | Пополнения словарей пользователем: `kind` brand/category, `payload` JSON, `note`, измеренный `effect`, `created_at`; уникально по (kind, payload) (Р-24) |
| `sent` | Что уже отправлено пользователю в push — память алертов (ОА-1) |
| `outbox` | Очередь сообщений ядра для бота (`kind`, готовый `payload`, `taken_at`) |
| `exports` | Реестр принятых выгрузок ФНС: sha256, число чеков, сколько новых, отброшенное, период |

Нормализованная таблица позиций — производная, на диск не пишется: держится в памяти сессии ядра
(`core/session.py`) вместе с отпечатком конфигов `Config.fingerprint` и пересобирается при его смене (Р-4).

## Инварианты расчёта
| Инвариант | Правило | Почему | Где в коде |
|---|---|---|---|
| Медиана цены | Только при ≥3 наблюдениях. Порог не снижать (Р-2) | Устойчивость к выбросам | `MIN_OBSERVATIONS = 3` в `profile/venues.py`, `profile/prices.py`, `matching/catalog.py` |
| Происхождение чисел | Все цены и суммы — из кода, не из модели (Р-26) | Проверяемость и повторяемость | `core/verify.py` |
| Окно свежести цен | Одно на систему (Р-27) | Сравниваются только современники | `history.PRICE_WINDOW_MONTHS` |

## Сопоставление товаров между магазинами
Метод — правила и словари, не эмбеддинги. Сравнение цен идёт только внутри одного SKU (SPEC §4):
- весовой SKU = (товарная группа, название), единица кг (Р-3);
- штучный SKU = группа · бренд · фасовка (`adapters/receipts_fns/sku.py`, бренды — `config/brands.json`);
- смешанные ключи, смена способа продажи и недостаток наблюдений отсекаются до ответа (Р-21).
Потолок сравнимости и очередь работ по нему — Р-24, Р-25.
