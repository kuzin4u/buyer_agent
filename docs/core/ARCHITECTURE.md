## Компоненты
| Компонент | Роль | Статус |
|---|---|---|
| Ядро (Python, только stdlib): `cli.py`, пакет `agent/` | Загрузка чеков, конвейер, расчёты, сравнение, сценарии 8.1–8.8 | есть |
| Хранилище состояния — SQLite `state.db` (`agent/store.py`) | Только изменяемое состояние, чеки не кладутся (Р-4). Таблицы: `settings`, `meta`, `rules`, `sent`, `outbox`, `exports` — см. DATA_MODEL | есть |
| Умный слой — «прокси модели» (`agent/core/smart.py`, `verify.py`) | Не отдельный сервис, а часть процесса ядра. Ключ `ANTHROPIC_API_KEY` читается из окружения сервера; без ключа слой выключен, работает базовый (Р-26) | есть |
| Веб-интерфейс (`web/`, FastAPI + Jinja + Chart.js локально) | Основной интерфейс: все восемь функций, план корзины, настройки, диагностика (Р-1, Р-23) | есть |
| Telegram-бот (`bot/`, aiogram, long polling) | Второй интерфейс: 8.2, 8.3, 8.4, уведомления, диплинки в веб. Транспорт: только HTTP API ядра, без хранения (ОА-1, Р-26) | есть |

## Главный принцип — разделение ролей
- **Языковая модель** (необязательно) выбирает функцию ядра и пересказывает её ответ.
- **Детерминированный код** считает цены, медианы, сравнение магазинов.
- Модель не выдаёт чисел от себя: каждое число её текста сверяется механически с
  фактами, показанными человеку; не нашлось — ответ отбрасывается целиком (Р-26, `verify.py`).

## Поток главного сценария
Базовый слой (всегда, без модели):
```
Запрос или кнопка → ядро: разбор регулярками (core/parse.py) → сценарий ядра
→ план корзины (agent/plan.py): три варианта — single (в одном месте),
  split (врозь, маршрут экономии), budget (под бюджет) → веб /plan или бот
```
Умный слой (только при заданном ключе, поверх базового):
```
Запрос → модель выбирает функцию и параметры → ФУНКЦИЮ ВЫПОЛНЯЕТ ЯДРО
→ модель пересказывает facts() → проверка чисел → не прошло — базовый слой
```

## Ограничения
- §3.3 SPEC: данные пользователя не расползаются — единственная точка хранения — сервер
  ядра; бот ничего не хранит (ОА-1). Исключение умного слоя — см. STATUS «Расхождения».
- Хостинг — VPS от 1 ГБ, один процесс, бот на long polling (Р-5, `docs/DEPLOY.md`).
  Конкретный провайдер не выбран ⟦уточнить⟧.

## Реальная структура (сверено по дереву файлов 23.09.2026)

- `agent/` — ядро: `core/` (parse, scenarios, session, smart, verify), `adapters/receipts_fns/` (loader, normalize, pipeline, rules, sku, report, diagnostics), `matching/` (catalog, budget), `profile/` (basket, prices, spending, venues, lapsed, build), плюс config, history, intake, plan, reach, store, export, settings
- `web/` — FastAPI-приложение: `app.py`, `templates/` (17 шаблонов: 15 страниц + `base`, `_chain`), `static/` (app.css, charts.js, vendor/chart.umd.min.js)
- `bot/` — Telegram-бот (тонкий): api, format, main
- `config/` — справочники: brands, categories, intents, normalization, shops
- `data/receipts.json` — датасет чеков (открыт); `data/inbox/` — принятые выгрузки ФНС (в .gitignore)
- `tests/` — 24 модуля `test_*.py` + `fixture.py` + `run.py` (unittest)
- Документы: `docs/DECISIONS.md` — журнал решений; набор Claude Code — в `docs/core/`
